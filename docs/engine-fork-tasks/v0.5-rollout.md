tree). Each engine fork (`wdunn001/sglang`, `wdunn001/vllm`,
`wdunn001/llama.cpp`, `wdunn001/text-generation-inference`) needs a
corresponding rollout PR. This document is the per-fork checklist.

## Task #76 — sglang OpenAI-bypass (T1.4)

**Goal:** when the engine receives a request with `stream_format: "msgpack"`
(or `"protobuf"` or any v0.5 binary variant), bypass the OpenAI-JSON-SSE
`list[int]` boxing path in `tokenizer_manager` and emit token IDs from a
buffer view (numpy uint32 / torch tensor / bytes) straight to the codec
frame encoder.

**Touch points in `wdunn001/sglang`:**
- `python/sglang/srt/entrypoints/openai/serving_completions.py:280` — branch
  on `request.stream_format`
- `python/sglang/srt/entrypoints/codec_frame.py:76` — accept
  `Union[List[int], array.array, np.ndarray, bytes]`

**Gate:** `CODEC_OPENAI_BYPASS=1`, default off. v0.4 + JSON-SSE clients
unchanged.

**Validation:** cross-stack bench cell wire bytes byte-identical between
`CODEC_OPENAI_BYPASS=0` and `=1`. Expected: ~25-40% codec-encode CPU
reduction per token at `=1`.

## Task #78 — delta-varint emit (T2.5)

The canonical Python reference encoder/decoder + 18-fixture conformance
suite landed in `packages/python/src/codecai/stream_delta.py` (commit
008826d). Each engine fork needs:

**TS/Rust/.NET/Java/C clients:**
- Add `encodeDeltaFrame` / `decodeDeltaFrame` to each client package.
- Cross-vocab fixtures: all 18 Python test cases produce identical
  bytes on each language.

**Engine forks (sglang/vllm/llamacpp):**
- Add `stream_format: "msgpack-delta"` / `"protobuf-delta"` to the
  request negotiation axis.
- Server-side encoder emits the delta-varint shape when negotiated.
- Engine-acceptance probe (`packages/bench/tests/test_engine_acceptance.py`)
  adds a 10th probe verifying the delta axis works end-to-end.

## Task #79 — well-known dict fetch (T2.8)

The canonical helpers landed across all 6 clients (commits 446fbbb → 0f6a495).
Each engine fork needs to add the boot-time dict-fetch path:

```
# Pseudocode for each engine fork's startup:
if os.environ.get("CODEC_ZSTD_DICT_MSGPACK_URL"):
    bytes = http.get(...)
    expected_hash = parse_hash_from_url(url)
    assert sha256(bytes).hexdigest() == expected_hash, "dict hash mismatch"
    zstd_registry.register("msgpack", bytes)
elif os.environ.get("CODEC_ZSTD_DICT_MSGPACK_PATH"):
    bytes = open(path).read()
    zstd_registry.register("msgpack", bytes)
else:
    # Either dict was baked into the image, OR hard-fail per
    # docs/RELEASE_CHECKLIST.md §1.7
    if not os.path.exists("/opt/codec/dicts/msgpack-v1.zstd"):
        raise RuntimeError("dict-availability gate (§1.7) failed")
```

Same pattern for `_PROTOBUF_URL` / `_PROTOBUF_PATH`.

**Validation:** §1.7 dict-availability gate in `docs/RELEASE_CHECKLIST.md`
passes for every published `wdunn001/codec-*:v0.5.0` image.

## Task #87 — bolt-on tool dispatch (sglang + vllm)

The contract is in `spec/versions/v0.5.md § "v0.5-5 — Bolt-on tool dispatch
(gateway side)"`. Three pieces per engine:

1. **Tool registry** — engine reads `CODEC_TOOL_MANIFEST_URLS` at startup,
   fetches each manifest, validates `tokenizerHash` against active model's
   tokenizer SHA-256. Mismatched tools load in `text-fallback` mode.
2. **MCP-style HTTP/IPC client** — when `ToolWatcher` detects a
   `<tool_call>` region, POST `CodecToolCall` (msgpack-framed) to the
   tool's `/codec/tool/v1/call` endpoint.
3. **Reinjection path** — `CodecToolResult.response_ids` inserted into the
   model's generation context where `<tool_call>` was detected. No
   detokenize/retokenize on the response.

**Gate:** `CODEC_BOLT_ON_DISPATCH=1`, default off. When off, the engine
surfaces `<tool_call>` regions to the client unchanged (existing v0.2-v0.4
behaviour).

**Reference SDK:** `@codecai/tool-kit` on npm (landed at v0.4.1).

## Task #89 — TGI as 4th cross-stack engine

**Goal:** Hugging Face TGI gains Codec patches; `wdunn001/codec-tgi:v0.5.0`
image ships; cross-stack matrix grows from 3 engines × 6 clients (24 cells
per encoding) to 4 engines × 6 clients (32 cells per encoding).

**Touch points:**
- New repo: `wdunn001/text-generation-inference` (fork of HF TGI).
- Add codec patches following the sglang/vllm pattern: `codec_frame.py`,
  `codec_compression.py`, `codec_version.py`, `codec_zstd_dict_registry.py`.
- Add a Codec-aware path in TGI's router/`generate_stream` for the
  `stream_format` axis.
- `codec-supervisor/` Dockerfile for the image (mirrors the
  `codec-{sglang,vllm,llamacpp}` Dockerfiles).
- Engine-acceptance pytest passes 9 protocol probes (per
  `packages/bench/tests/test_engine_acceptance.py`).

**Why TGI is the v0.5 4th engine pick:** largest production-deployment base
not yet covered. Hugging Face's adoption pulls Codec into the OIP v2
trajectory (since TGI implements OIP v2 today; the Codec extension proposal
in `docs/submissions/oip-proposal.md` lands cleanly via TGI).

## Cross-fork tracking

This document is the source of truth for the v0.5 engine-fork rollout.
When a fork lands its half of a task:

1. Open the fork's PR with the title `v0.5: <task name> (Codec #<id>)`.
2. Link the PR URL back here under the task's row.
3. Mark the task complete in the v0.5 release-checklist only when ALL
   forks listed in the table above have landed their half.

No fork PR can ship before:
- The canonical package change has landed in this tree (this tree's
  commit hash referenced from the fork's commit message).
- The 18-fixture conformance corpus (#78) for cross-language byte
  equality is captured.
- The release-checklist's §1.5 prior-version compat gate passes against
  the fork's RC image.
